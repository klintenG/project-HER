## Changes in this review

- Thumbnail generation selects one transparent portrait/object, preferring a named primary character, and uses the editorial background palette and bundled Poppins typography with the script's existing 3–8-word hook. It buys no additional images. A brief 1.1–1.9-second opening interval contains the cover so Buffer's 1,500-ms Instagram cover selector can use it. Audio/caption timestamps and video duration are preserved. Cover embedding incurs an extra H.264 encoding pass. Classic/non-cutout output retains the frame fallback.
- Editorial visual planning previously accepted six subjects as sufficient even when the diversity target was twelve. It now requests its one permitted repair up to the full story-relative target. Supported smaller plans remain valid with diagnostics instead of introducing filler or unbounded costs. Existing entity capacity is 24 and image-request capacity defaults to 24; neither is a four-image cap. A 10–12-image result still depends on the spoken subjects, provider success and budget.
- The middle Made with/projectHER credit already existed. Its default hold is now 1.8 seconds plus two 0.45-second fades, totaling about 2.7 seconds. Explicit branding overrides remain supported. Both render compositions use the shared controller.
- Create video → Ready queue runs generation without scheduling. Worker records now persist story, renderer, cover/validation and upload progress; dashboard polls every five seconds and keeps updating operations during video playback. Progress percentages represent workflow stages, not a measured time-to-completion estimate.
- Separate Ready, Scheduled and Published filters improve queue navigation. Validated ready/scheduled story cards expose Publish now for Instagram and YouTube through Buffer. Existing scheduled posts are moved using editPost/shareNow; unused videos create shareNow posts. Durable records, the shared publication lock and unknown-outcome quarantine prevent blind duplicate create attempts. Remote verification remains necessary to establish publication.
- Deployment no longer sets enabled/live-validated/dry-run values on every rollout. Existing publishing state is preserved; deployment is not evidence of platform validation.

## Recommended next improvements

1. Pin the same immutable image digest on web and worker; report that digest, source commit and pipeline configuration version in authenticated dashboard diagnostics. Roll out both together, smoke-test, and retain a rollback revision.
2. Show planned/acquired/displayed distinct image counts separately, visual fallback reasons and the supporting scene plan on each story. Alert on a sustained diversity drop; avoid enforcing arbitrary image quotas on short stories.
3. Add an authenticated production fixture smoke test before routing traffic: verify the cover frame, middle credit, last narrated event, audio and final platform payloads. Preserve those artifacts with each release.
4. Reconcile immediate-publication unknown outcomes in a dedicated operator workflow, including cases where a create response lost its remote ID. Do not automatically recreate uncertain posts.
5. Replace optional long-lived browser-token persistence with short-lived server sessions, and add progress history/heartbeats with stale-worker alerts. Keep paid generation retries separate from delivery retries.
6. Measure rendering/cover encoding latency and costs before changing worker CPU, concurrency or ready-queue targets. Render the cover directly as a shared Remotion component in a future optimization to avoid the second encoding pass.
